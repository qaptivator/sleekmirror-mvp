PROJECT STRUCTURE
-----------------
Nuxt 4 Full-Stack Framework with Nitro Server Engine
├── Frontend: Vue 3 + Nuxt components + Pinia store
├── Server: Nitro engine with file-based API routing
└── Database: MongoDB with Mongoose ORM

Tech Stack:
  • Nuxt 4.4.8 (SSR + API routes)
  • Nitro (built-in server)
  • Mongoose 9.7.0 (MongoDB ORM)
  • TypeScript
  • OpenAI 6.43.0 (for future AI integration)
  • Pinia 3.0.4 (state management)
  • Tailwind CSS 4.3.1 (styling)

================================================================================
                         API ROUTING CONVENTION
================================================================================

Nitro File-Based Routing:
  Pattern: [route].[method].ts
  Dynamic segments: [param] in filename
  HTTP methods: get, post, put, delete, patch, etc.

Generated Routes:

1. FILE MANAGEMENT
   POST   /api/files                 Upload file (multipart/form-data)
   GET    /api/files                 List user's files
   GET    /api/files/[id].json       Get file metadata
   GET    /api/files/[id].file       Download file binary

2. SCAN CHECKS
   POST   /api/checks/run            Execute a scan/check
   GET    /api/checks/[id]           Retrieve check results

3. USER MANAGEMENT
   GET    /api/users                 Lookup user by identifier


================================================================================
                        DATABASE MODELS & SCHEMAS
================================================================================

USER MODEL
----------
Schema: identifiers, credits, first_name, last_name, timestamps
Collection: users
Purpose: User profiles and credit management
Sample Doc:
{
  _id: ObjectId,
  identifiers: ["email:user@example.com"],
  credits: 10,
  first_name: "John",
  last_name: "Doe",
  createdAt: Date,
  updatedAt: Date
}


FILE MODEL
----------
Schema: user (ObjectId, indexed), filename, mime_type, size_bytes, binary_data
Collection: files
Purpose: Store uploaded image/file data
Max Size: 4 MB (enforced at API layer)
Sample Doc:
{
  _id: ObjectId,
  user: ObjectId (references User),
  filename: "photo.jpg",
  mime_type: "image/jpeg",
  size_bytes: 2048576,
  binary_data: Buffer,
  createdAt: Date,
  updatedAt: Date
}

Note: binary_data excluded from list queries using .select('-binary_data')


CHECK MODEL
-----------
Schema: user, file, context_tag, overall_score, verdict_headline, categories, action_checklist
Collection: checks
Purpose: Store scan/analysis results
Nested Schema (categorySchema): score (0-100), feedback, fix

Sample Doc:
{
  _id: ObjectId,
  user: ObjectId (references User, indexed),
  file: ObjectId (references File),
  context_tag: "mirror_check",
  overall_score: 85,
  verdict_headline: "Clean shoulder alignment, but your shirt collar needs adjustment.",
  categories: {
    outfit: {
      score: 90,
      feedback: "Excellent fitting.",
      fix: "None."
    },
    grooming: {
      score: 80,
      feedback: "Clean finish.",
      fix: "None."
    },
    presentation: {
      score: 65,
      feedback: "Collar is warped on the left side.",
      fix: "Straighten left collar point flush."
    }
  },
  action_checklist: [
    "Straighten left collar point flush before leaving."
  ],
  createdAt: Date,
  updatedAt: Date
}

FILE ENDPOINTS
==============

1. POST /api/files - Upload File
   ─────────────────────────────
   Authentication: REQUIRED
   Request Format: multipart/form-data
     - Field name: 'file'
     - Body: binary file data
   
   Response (201 Created):
     { file_id: ObjectId }
   
   Constraints:
     - Max file size: 4 MB
   
   Error Codes:
     - 400: Missing auth, missing form data, no file detected, file too large
     - 401: Unauthorized (no user context)
   
   Database Operation:
     File.create({
       user: currentUser._id,
       filename: filePart.filename,
       mime_type: filePart.type,
       size_bytes: filePart.data.length,
       binary_data: filePart.data
     })


2. GET /api/files - List User Files
   ──────────────────────────────────
   Authentication: REQUIRED
   Parameters: None
   
   Response (200 OK):
     [
       {
         _id: ObjectId,
         user: ObjectId,
         filename: string,
         mime_type: string,
         size_bytes: number,
         createdAt: Date,
         updatedAt: Date
       },
       ...
     ]
   
   Details:
     - Returns array of File objects for authenticated user
     - binary_data field excluded from response
     - Sorted by createdAt in descending order (newest first)
     - Lightweight response suitable for file listing UI
   
   Error Codes:
     - 401: Unauthorized


3. GET /api/files/[id].json - Get File Metadata
   ──────────────────────────────────────────────
   Authentication: REQUIRED
   Route Parameters:
     - [id]: File MongoDB ObjectId
   
   Response (200 OK):
     {
       _id: ObjectId,
       user: ObjectId,
       filename: string,
       mime_type: string,
       size_bytes: number,
       createdAt: Date,
       updatedAt: Date
     }
   
   Details:
     - Returns file metadata only (no binary data)
     - Access control: Verifies file.user === currentUser._id
     - Uses .lean() for better performance
   
   Error Codes:
     - 401: Unauthorized
     - 404: File not found or access denied

     - [id]: File MongoDB ObjectId
